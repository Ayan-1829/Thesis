Before we start

Why this matters

Two months of work: your model is 0.4% better than the baseline. Your examiner asks: “Would it still be better with a different random seed?” You do not know.

Experiments are only as convincing as their setup: clean splits, no leakage, several runs, the right metrics and a test of whether differences are real.

This chapter turns “I trained a model” into “I can show, with evidence, that the method works — and why”.

Part 1 of 11

Getting and preparing data

  • Public datasets: cite the paper that introduced them; check the licence.
  • Your own data: plan collection, consent and storage (chapter 9); write a labelling guide.
  • Labelling: at least two annotators on a sample; report agreement (Cohen’s κ).
  • Clean: remove duplicates and broken items; document every rule.
  • Describe: size, classes, class balance, sources, time period.

A datasheet for your data

Who collected it, when, how, for what purpose; what each label means; known gaps and biases; licence and how to access it. Put it in an appendix.

Data

Train, validation and test

  • Train: the model learns from it.
  • Validation: you tune hyperparameters and choose models with it.
  • Test: used once, at the end, to report the result.
  • Split before any analysis; keep class balance (stratify).
  • For small data use k-fold cross-validation: every item is tested exactly once.

Part 5 of 11

Running experiments

  • Start with the simplest baseline end to end; then add complexity.
  • Change one thing at a time and record it.
  • Fix and record random seeds; run each setting 3–5 times.
  • Give every method the same tuning budget.
  • Log every run: config, commit hash, metrics, time (a spreadsheet, or MLflow / Weights & Biases).

Part 6 of 11

Measuring results: the confusion matrix

Measuring

Is the difference real?

  • Report mean ± standard deviation over several runs or folds.
  • Two methods on the same folds or seeds: paired t-test, or Wilcoxon signed-rank if the differences are not normal.
  • Two classifiers on one test set: McNemar’s test.
  • Several methods on several datasets: Friedman test with a post-hoc test.
  • p < 0.05 means the difference is unlikely to be chance — not that it is large or important. Report the size too.
With one run and no variance, a difference of 0.3% tells you nothing.

Analysis

Presenting results

  • A main results table: methods × metrics, mean ± sd, best in bold, the test of significance noted.
  • Plots: learning curves, per-class bars, confusion matrices, examples.
  • Every figure and table numbered, captioned, and discussed in the text.
  • Say what the numbers mean, not only what they are.

Worked example 1 of 3

Worked example 1

A model for detecting pneumonia is trained and tested on X-ray images split randomly. Many patients have several images. Is there a problem?
Show the solution
Yes: images of the same patient appear in both train and test, so the model can recognise the patient rather than the disease — leakage. Split by patient ID so that each patient’s images are all in one split, and report the result again.

Worked example 2 of 3

Worked example 2

Confusion matrix for “phishing” as positive: TP = 90, FN = 10, FP = 30, TN = 870. Compute precision, recall, F1 and accuracy.
Show the solution
Precision = 90 ÷ (90 + 30) = 0.75. Recall = 90 ÷ (90 + 10) = 0.90. F1 = 2 × 0.75 × 0.90 ÷ 1.65 = 0.818. Accuracy = (90 + 870) ÷ 1000 = 0.96. Accuracy looks excellent; precision shows one in four alarms is false.

Worked example 3 of 3

Worked example 3

Method A: F1 over 5 seeds 0.80, 0.82, 0.81, 0.79, 0.83. Method B on the same seeds: 0.78, 0.80, 0.80, 0.77, 0.80. How do you report and test it?
Show the solution
Means: A 0.810 ± 0.016, B 0.790 ± 0.014. Differences A − B: 0.02, 0.02, 0.01, 0.02, 0.03; mean 0.02, sd 0.0071; t = 0.02 ÷ (0.0071 ÷ √5) ≈ 6.3 with 4 degrees of freedom, p ≈ 0.003. A is significantly better, by about 2 F1 points — a small but consistent gain.

Practice

Practice (1 of 2)

Try each one yourself first, then check the answer.

1. What is each split for: train, validation, test?
Show the answer
Train: fit the model. Validation: tune and select models. Test: report the final result, used once.
2. Give three examples of data leakage.
Show the answer
Duplicates across splits; the same patient/user in train and test; random splits of time series; normalisation fitted on all data; tuning on the test set.
3. Why run each experiment with several seeds?
Show the answer
Results vary with initialisation and data order; several runs give a mean and standard deviation and allow a significance test.

Practice

Practice (2 of 2)

Try each one yourself first, then check the answer.

4. Which test compares two methods evaluated on the same 10 folds?
Show the answer
A paired t-test (or the Wilcoxon signed-rank test if the differences are not normally distributed).
5. What is the difference between an ablation study and error analysis?
Show the answer
Ablation removes components to measure their contribution; error analysis studies the mistakes to understand why the method fails.
6. List four things that make an experiment reproducible.
Show the answer
Code in Git with a tagged version; environment with versions; recorded seeds and configs; scripts that regenerate every table and figure; released data/models or an explanation; a README.

Summary

Summary

  • Describe and document your data; measure label agreement; check licences.
  • Split into train, validation and test (or use cross-validation); test once, at the end.
  • Prevent leakage: no duplicates or subjects across splits, time-based splits, fit pre-processing on train only.
  • Run several seeds, log every run, give every method the same tuning budget.
  • Report mean ± sd and test whether differences are real; add ablation and error analysis.
  • Make every number reproducible: Git, environment, seeds, scripts, README.
